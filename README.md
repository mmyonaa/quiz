# quiz

> 정보처리기사 필기를 4지선다로, 실기를 필답형으로 풀고 즉시 채점과 해설을 받는 정적 연습장.
> 정보보안기사도 같은 화면으로 함께 연다(`/sec/`).
> [daily.mcp](https://mmyonaa.github.io/blog/) 블로그의 자매 프로젝트 — 문제의 해설이 블로그의 개념 글로 이어진다.

**사이트**: https://mmyonaa.github.io/quiz/

## 기능

- **소개**(`/about`): 이 사이트가 무엇이고 무엇으로 만들어졌는지 — 지금 담긴 것(문항·주제·카드 수),
  화면마다 무슨 자리인지, 발행 게이트·병합 도구·현황 리포트로 품질을 어떻게 지키는지, 세 가지 원칙.
  **숫자는 손으로 적지 않는다** — 전부 빌드 타임에 은행에서 센다(소개 글이 서술로 들고 있으면 가장 먼저 낡는다).
  [daily.mcp 블로그의 /about/](https://mmyonaa.github.io/blog/about/)과 짝이다. 헤더 메뉴 끝과 푸터에서 들어간다.
  현황 표는 **갈리는 것만** 싣는다 — 두 시험이 같은 값인 항목(과목·영역 구성, 필기 시험 형식)은 표 밖 한 줄로
  합쳐진다. 어느 줄이 같은지는 못 박지 않고 그때의 값으로 판정한다. 시험 축이 없는 공용 페이지(소개·마이페이지)는
  헤더에 `shared`를 넘겨 시험 전환 탭의 활성 표시를 걷는다 — 두 시험을 함께 말하는 자리에서 한쪽이 켜져 있으면
  "지금 그 시험을 보는 중"이라는 거짓이 된다
- **홈**: 연습 · 모의고사 · 오답노트 · 암기 노트를 모드 카드로 먼저 고르고, 조건 설정은 고른 뒤에 온다.
  빠른 연습이 주 행동으로 한 줄을 쓰고 나머지는 보조로 내려가며, 오늘 복습할 오답이 있으면
  오답 카드가 주 행동을 넘겨받는다
- **필기 연습 모드**: 영역·문항 수·난이도를 골라 출제, 즉시 채점과 해설.
  채점 방식은 **제출 후 한꺼번에**(기본)와 **고르면 바로 확인** 중 고르며 기기에 기억된다 —
  바로 확인은 고른 순간 정오·정답·해설을 그 자리에 펴고 보기를 잠근다(모의고사는 늘 제출 후다)
- **필기 모의고사**: 실제 시험 비중의 100문항·150분 타이머, 과목별 과락(40점)/평균 60점 합격 판정,
  실제 OMR처럼 문항별 ①~④를 마킹하는 답안 표기란
- **실기 필답 연습**(`/practical`): 보기 없이 답을 직접 입력 — 단답·계산·코드 출력·SQL은 자동 채점,
  약술형은 모범답안·핵심어 대조 후 자가 채점. 실기 모의고사는 20문항·150분·문항당 5점·60점 합격
- **오답노트**: 오답 자동 누적, 오답만 다시 풀기. 맞히면 바로 지우지 않고 **1일 → 3일 → 7일**로
  다시 볼 시점을 미루며, 마지막 단계를 통과하면 졸업한다. 홈은 쌓인 양보다 "오늘 복습할 오답 N개"를
  먼저 말한다. 시험별로 따로 쌓이고, 개념 노트의 확인 문제도 같은 통에 쌓인다
- **개념 노트**(`/notes`): 해설을 영역·주제별로 모아 읽는 페이지 — 주제마다 개념 정의로 시작하는 도입부, 그 아래 시험 포인트 해설과 정답을 가린 확인 문제, 블로그 개념 글 링크
- **암기 노트**(`/memo`, `/sec/memo`): 개념 노트가 "왜"를 읽는 자리라면 여기는 "무엇"만 외우는 자리 —
  줄글 없이 두문자·표·순서 흐름·계층 스택·타일로 모은 카드 79장이 두 시험에 93자리로 선다(본문이 겹치는 카드는 한 벌만 둔다). 정처기 42장 · 정보보안기사 51장(46개 주제 전부 보유)으로,
  OSI 7계층과 계층별 보안 프로토콜·공격, 포트, 인증 4유형, 접근 통제, 암호 분류, 정규화, 결합도·응집도,
  자료구조·정렬·시간복잡도, UML·SOLID·개발 방법론, 블록 운영 모드·PKI, 리눅스 로그·윈도우 인증,
  웹 공격·DNS·공급망, 위험 관리·BCP·법규 숫자까지 담는다.
  정보보안기사 쪽은 실기 기출(29회)이 묻는 자리를 기준으로 채웠다 — 취약 함수(`strcpy`·`gets`)·보안 솔루션 약어·
  인증서 고정·파일 업로드 우회·법률 용어 정의·이벤트 로그 크기 산정처럼 **구체적 산출물**을 묻는 유형이다.
  **가리기**를 켜면 외울 값(값 칩·형광펜)이 빨간 시트처럼 덮이고 눌러서 하나씩 확인한다.
  카드마다 **외웠다** 표시를 남겨 영역별·전체 진행이 쌓이고, '외운 것 숨기기'로 남은 것만 본다 —
  채점이 아니라 자기 선언이라 오답노트와 섞지 않고 따로 쌓는다(`daily.quiz.memo-done`, 시험별로 갈린다).
  카드마다 그 주제의 개념 노트로 가는 `개념 →` 링크가 붙고, 홈 모드 카드에서도 바로 들어간다
- **학습 기록**: 홈과 실기 홈이 최근 7일의 푼 문항 수·정답률·연속 일수를 출석부로 보여 준다.
  날짜별 합계만 이 기기(`localStorage`)에 남으며 시험별로 갈린다 — 무엇을 틀렸는지는 오답노트가 갖는다.
- **계정·개인화**(Supabase): Google 로그인, 문제·개념 저장(북마크), 오답 자동 기록, 마이페이지 보관함.
  로그인 전에도 마이페이지는 이 기기에 쌓인 오답노트를 시험별로 보여 준다(계정 기록과 별개인
  localStorage 기록이라 브라우저를 지우면 사라진다 — 로그인하면 계정에 남는다)

## 구조

서버 없이 동작한다. 문제·정답·해설을 빌드 타임에 HTML로 굽고, 출제·채점은 브라우저 안에서 끝난다.
유저 데이터(북마크·오답 기록)만 Supabase에 저장하며 RLS로 사용자별 격리한다.

- **문제 은행**: 필기 `src/data/questions.json`, 실기 `src/data/practical.json` — 콘텐츠 컬렉션 + zod 스키마(`src/content.config.ts`)가 발행 게이트. 스키마 위반 문제는 빌드가 실패한다.
  규모는 정처기 필기 515 · 실기 100, 정보보안기사 필기 436 · 실기 54 (주제 137개).
- **문항 추가**: 초안 JSON을 `scripts/written-merge.mjs`(필기) · `scripts/practical-merge.mjs`(실기)로
  병합한다. 은행에 **쓰이기 전에** 검증하고, 특히 zod가 원리상 못 보는 것 — 문항 사이의 id·발문
  중복 — 을 잡는다. `--dry`는 검증만, `--report`는 은행 현황과 다음에 낼 주제를 고른다.
- **보기에서 답이 유도되는 것**도 게이트와 리포트가 본다. 둘로 갈리는데, 가르는 기준은
  **정답이 화면에 이미 보이는가**다.
  - 실기는 답을 직접 적으므로 발문·제시문에 정답 표기가 있으면 **베껴 적으면 정답 처리된다** —
    이건 명백한 결함이라 `practical-merge.mjs`가 막는다. 판정에는 채점기의 `normalize`를
    그대로 써서 "베껴 적은 문자열이 실제로 정답으로 받아들여지는가"를 본다. 제시문에서 답을
    골라내는 것이 문제의 핵심인 문항은 `STEM_LEAK_OK`에 id를 적어 예외로 둔다(적는 일 자체가
    의도의 기록이다).
  - 필기는 정답이 보기 중 하나로 이미 보이므로 같은 규칙이 성립하지 않는다(발문이 뜻을
    설명하고 보기에서 이름을 고르는 것은 정상 유형이다). 결함은 보기 묶음의 **모양**이
    정답을 가리키는 쪽이고 한 문항만 보면 판단할 수 없어, `--report`가 은행별 치우침을
    숫자로 보여 준다 — 정답 위치 분포, 정답지만 유난히 길거나 짧은 문항 수, 정답지만
    괄호·영문을 받은 문항 수, 부정형 발문 비율과 그중 정답지에 절대어가 붙은 수.
    **막지 않고 보이게만 한다** — 모두 정당한 예외가 있는 지표다.
- **실기 채점**: `src/lib/practical-grade.ts` — 시험별 실기 형식(`PRACTICAL_FORMAT`)의 단일 정의를 갖는다.
  브라우저로도 번들되므로 `content.config.ts`에 의존하지 않고, 반대로 그쪽이 여기를 읽는다.
  표기 요동(대소문자·띄어쓰기·전각·낱말 하이픈)을 정규화로 흡수하고, 뜻이 같은 다른 낱말은 문항이 허용 표기 목록으로 나열한다. 그래도 새는 표기는 사용자가 "이 표기도 정답 처리"로 로컬에 덧붙인다.
- **외운 카드**: `src/lib/memo-done.ts` — 암기 노트의 "여기까지 외웠다"를 기기에 남긴다
  (`daily.quiz.memo-done`, 정처기는 접미어 없음 · 정보보안기사는 `.sec`). 문항이 없어 맞고 틀림을
  기계가 가릴 수 없으므로 **채점이 아니라 자기 선언**이고, 그래서 오답노트의 복습 간격 체계를
  빌리지 않고 켜고 끄는 표식 하나로 둔다 — 틀린 기록이 아닌 것을 섞으면 "오늘 복습할 오답 N개"의
  뜻이 흐려진다.
- **학습 기록**: `src/lib/history.ts` — 날짜별 "푼 문항 수 · 맞힌 수"만 브라우저에 남기고
  (`daily.quiz.history.v1`, 시험별로 갈린다) 홈의 출석부 띠를 그리는 일까지 여기서 한다.
  필기·실기 홈이 같은 함수를 부른다. 무엇을 틀렸는지는 오답노트(`wrong-note.ts`)의 몫이다.
- **문제 원칙**: 기출 복제가 아닌 자체 제작 문항. 전 문항 하/중/상 난이도 라벨. 코드 출력 문항은 실제 실행으로 정답을 검산한다.
- **시험 축**: `exam`이 영역·과목·시험 형식을 가른다(`src/content.config.ts`의 `AREAS_BY_EXAM`·`SUBJECTS_BY_EXAM`·`EXAM_FORMAT`).
  문항은 시험을 직접 갖지 않고 주제를 통해 물려받는다. `topic-notes.json`에서 `exam`을 생략하면 정처기다.
  URL은 정처기가 접두어 없이(`/`, `/notes/…`), 정보보안기사가 `/sec/…`로 나가며 라우트 파일은 한 벌을 공유한다
  (`src/pages/[...exam]/`의 rest 파라미터 — 필기·실기·개념 노트·암기 노트 모두).
  브라우저 저장 키도 시험별로 갈린다(정처기는 접미어 없음, 정보보안기사는 `.sec`) — 오답노트와
  중단 세션이 시험을 넘어 서로 덮어쓰지 않게 하기 위해서다.
- **암기 카드**: `src/data/memo-notes.json`이 카드의 단일 정의 — 요약하는 **주제 목록**·제목·두문자(선택)·본문.
  카드는 시험·영역을 직접 들지 않고 주제에서 물려받는다(문항과 같은 방식). 주제를 시험마다 하나씩 들면
  **본문 한 벌이 두 시험에 함께 선다** — OSI 카드는 정처기에서 `네트워크`, 정보보안기사에서 `네트워크 보안`에
  놓인다. 카드 79장이 93자리를 채우며(정처기 42 · 정보보안기사 51), 카드마다 그 주제의 개념 노트로 가는
  `개념 →` 링크가 붙는다. 본문은 개념 도입부와 같은 블록 표기(`> ` 콜아웃 · `| ` 대조표 · `- ` 목록)와
  강조 3층에 더해 시각 블록 셋을 쓴다 — `~ ` 순서 흐름(핸드셰이크·정규화 단계·절차), `# ` 계층 스택
  (한 줄이 한 층, 칸은 `|`, 첫 줄 `#= `는 머리글: OSI 7계층·복구 사이트), `* ` 타일(`이름 | 설명`:
  인증 4유형·DoS 공격). 렌더러는 `src/components/MdBlocks.astro` 하나를 개념 노트와 같이 쓴다.
  게이트(`content.config.ts`)는 없는 주제·한 시험에 주제 둘·백틱 짝·칸 수(표·스택은 줄마다 같게, 타일은
  두 칸)·줄머리 섞임·100자 형광펜·카드당 형광펜 2개를 본다. 도입부와 다른 점 하나 — 형광펜 0개를 허용한다
  (포트 번호 표처럼 카드 전체가 외울 값인 것은 칠할 한 줄이 없다). 문항은 붙지 않으며, 카드가 있는
  시험에만 라우트와 헤더 메뉴가 난다.
- **개념 주제**: `src/data/topic-notes.json`이 주제의 단일 정의 — 시험·과목·영역·제목·자족적 도입부·연결할 블로그 글(선택). 필기와 실기가 같은 주제 집합을 공유하며, 문항은 `topic`으로 주제에 속하고, 없는 주제를 쓰면 빌드가 실패한다. 주제는 블로그와 분리돼 있어 글이 없어도 도입부로 완결된다.
- **본문 강조**: `src/lib/md.ts`가 단일 정의 — 도입부·해설·발문이 모두 이 규칙을 쓴다.
  `==형광펜==`(외울 한 줄·대조 짝·함정), `**용어**`, `` `값` ``(수치·명령·경로).
  형광펜은 도입부에 한둘, 해설에는 하나까지다. 열거를 통째로 칠하지 않고 분류 이름은 굵기로
  내리며, 설명구까지 한 덩어리로 길게 칠하면 표시가 아니라 문단이 되어 눈이 갈 곳을 잃는다.
  면·굵기·글꼴로 축이 갈리므로 한 문장에 셋이 같이 와도 구분된다. `> `로 시작하는 문단은
  시험 포인트 콜아웃, `| `로 시작하는 문단은 대조표다(축이 셋 이상일 때만 쓴다). 코드의 `==`는 양옆 공백 덕에 형광펜으로 잡히지 않지만(`i % 2 == 1`),
  공백 없는 `a==b`를 한 문단에 둘 이상 쓸 때는 백틱으로 감싼다.
  규칙은 문서가 아니라 `src/content.config.ts`의 게이트가 강제한다 — 형광펜 없는 도입부,
  도입부 3개 이상·해설 2개 이상의 형광펜, 100자 초과 형광펜, 홀수 백틱(도입부·발문·해설·
  모범답안)은 빌드가 실패한다. 게이트는 개수만 볼 수 있으므로, 영역별로 해설의 몇 %가
  형광펜을 들고 있는지는 `written-merge.mjs --report`가 따로 보여 준다 — 10~20%를 벗어나면
  위아래 모두 경고한다(과하면 노란 벽, 평평하면 들고 갈 것이 안 보인다).
- **영역**: 정처기는 운영체제 · 네트워크 · 데이터베이스 · 소프트웨어공학 · 정보보안 · 프로그래밍,
  정보보안기사는 보안 일반 · 암호학 · 시스템 보안 · 네트워크 보안 · 애플리케이션 보안 · 보안관리·법규
- **화면 토큰**: `src/styles/global.css` 머리의 `:root`가 단일 정의 — 타입 7단(`--t-2xs`…`--t-3xl`),
  간격(`--s-1`…`--s-6`), 모서리 3단(`--r-sm`·`--radius`·`--r-pill`), 읽기 폭(`--measure` 42rem ·
  `--measure-wide` 52rem), 색. 새 크기·여백이 필요하면 단을 늘리지 말고 가까운 단을 쓴다
  (고유 `font-size`가 24종까지 불어났던 적이 있다).
  색에서 갈라 두는 축이 둘이다 — **액센트는 시험별로 바뀌고**(정처기 코랄 / 정보보안기사 블루)
  **정답의 `--ok`와 오답의 `--wrong`은 두 시험이 공유한다**. 정오답에 액센트를 쓰면
  정보보안기사에서 "틀렸다"가 브랜드 블루가 된다.
- **화면 규약**(성격: 문제집 + 개발자 노트). 새 화면을 붙일 때 이 네 가지를 따른다.
  1. **읽기 폭**: 문장이 본문인 것은 `--measure`, 막대·표가 섞인 것은 `--measure-wide`까지만 쓴다.
     셸 전폭(1240px)으로 흘리면 한 줄이 65자를 넘는다.
  2. **카드는 "고를 수 있는 것"에만**. 읽는 것(개념 항목·해설·성적표 행·목차)은 면과 테두리를
     걷고 괘선(`border-bottom`)으로 끊는다. 같은 박스가 여러 장 쌓이면 위계가 아니라 겹이 된다.
  3. **mono는 역할이다**: 세는 것·재는 것·표기하는 것(문항 번호·진행·타이머·점수·개수·라벨)에
     쓰고, 읽는 문장에는 쓰지 않는다. 숫자에는 `tabular-nums`를 함께 준다.
  4. **정오는 표식으로**: `○`/`✕`와 좌측 규칙으로 말하고 판을 통째로 칠하지 않는다. 채워진
     액센트는 한 화면에 하나(주 행동)만 둔다.
- **블로그 동기화**: `scripts/blog-sync.mjs` — prebuild 링크 검증·제목 자동화(`--check`),
  그 주에 생긴 일만 담는 주간 리포트(`--report`: 죽은 링크·글 개정·새 커버리지 갭),
  아직 메워지지 않은 자리 전량(`--backlog`: 커버리지 갭·글 연결 갭). 커버리지 갭은 두 시험
  섹션(`jeongcheogi`·`boangisa`) 글만 센다 — MCP·개발기 글은 붙을 주제 축이 없다

## 개발

```bash
npm install
cp .env.example .env   # Supabase URL·anon key (없어도 문제 풀이는 동작)
npm run dev            # http://localhost:4322/quiz/ (블로그 dev 4321과 분리)
npm run build          # prebuild로 blog-sync --check가 먼저 돈다 — 죽은 글 링크는 빌드 실패
npm run preview        # 빌드 결과를 4322로 서빙
npm run check          # astro check — .astro 파일까지 보는 타입 게이트
npm run sync-report    # 주간 리포트를 로컬에서 뽑아 본다 — sync-state.json을 갱신하므로
                       # 커밋할 생각이 없으면 실행 후 되돌릴 것(보고 이력이 상태에 남는다)
npm run sync-backlog   # 남은 커버리지 갭·글 연결 갭 목록(상태를 건드리지 않는다)
```

## 배포

main push 시 GitHub Actions(`.github/workflows/deploy.yml`)가 GitHub Pages로 배포한다.
Supabase 키는 Actions 시크릿(`SUPABASE_URL`, `SUPABASE_ANON_KEY`)으로 주입된다.

Supabase 무료 플랜은 **7일간 DB 활동이 없으면 프로젝트를 일시정지**하고, 그러면 로그인·오답노트가
함께 멈춘다. `supabase-keepalive.yml`이 매일 실제 테이블을 한 번 읽어 이를 막는다 — 헬스체크
엔드포인트는 DB를 건드리지 않아 활동으로 집계되지 않으므로 핑 대상을 테이블에서 옮기지 말 것.

`sync-report.yml`은 매주 월요일 블로그 싱크를 돌리며, 보고를 **사건**과 **백로그**로 가른다.
주간 이슈에는 그 주에 생긴 일(죽은 링크 · 글 개정 · 새로 생긴 커버리지 갭)만 담고, 보고한 것은
`sync-state.json`에 남아 다시 실리지 않는다 — 조용한 주에는 이슈가 아예 열리지 않는다.
아직 메워지지 않은 자리(커버리지 갭 · 글 연결 갭)는 상시 이슈 하나의 본문을 매주 덮어쓴다.
