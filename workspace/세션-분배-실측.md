# 세션 분배 실측

같은 레포에 Claude 세션이 둘 이상 붙었을 때, 분배·조율이 예상과 달랐던 건을 한 줄씩 적는다.
형식은 `상황 · 예상 vs 실제 · 바꿀 대상`이다. 예상대로 굴러간 건은 적지 않는다 — 여기 쌓이는
것은 훅이나 규칙을 고칠 근거이지 작업 일지가 아니다.

## 2026-10-22 · 같은 작업 트리를 쓰는 두 세션이 서로의 미커밋 변경을 커밋에 쓸어 담았다

- **상황** — 세션 둘(이 세션과 quiz-38)이 같은 작업 트리에서 `feat/136-note-abbr-expansions`를
  공유하며 `src/data/topic-notes.json`·`questions.json`을 동시에 고쳤다.
- **예상 vs 실제** — `git add <파일>` 전에 `git diff --stat`으로 남의 변경이 섞였는지 보면
  갈라 담을 수 있다고 봤다. 실제로는 **양방향으로 한 번씩 섞였다.** (1) 상대가 `git add` 했을 때
  내 미커밋 `Trinoo`/`Stacheldraht` 교체가 상대 커밋 `0bfe0c4`에 들어갔다. (2) 내가 `--stat`을
  확인한 뒤 `git add` 하기까지 수십 초 사이에 상대의 보기 수정 5건이 들어와 내 커밋 `de14b99`에
  담겼다(확인 시점 4줄 → 커밋 9줄). 확인과 스테이징 사이의 틈이 구조적으로 남아, 조심해서
  막을 수 있는 종류가 아니다.
- **바꿀 대상** — `~/claude-shared/core-tools/bin/peer-check.sh:89,150`. 지금은 같은 트리를
  "주의하라"고만 말하고 `git worktree` 분리를 권고로 둔다. 같은 트리 + 같은 파일이 확인되면
  권고가 아니라 분리를 먼저 묻는 쪽이 맞다. 커밋 직전 `--stat` 확인은 대책이 못 된다는 것을
  훅 문구에도 적는다.
