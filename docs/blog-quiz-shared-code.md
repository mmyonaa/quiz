# blog ↔ quiz 공통 코드 실측 — core 레포를 세울지

daily.quiz(이 레포)와 daily.mcp 블로그([mmyonaa/blog](https://github.com/mmyonaa/blog))는 같은
사람이 만든 자매 사이트고, 이 레포의 문항은 저쪽 개념 글을 바탕으로 생성된다. 그래서 "공통
부분을 core 레포로 빼고 두 레포가 그걸 바라보게 하자"는 안이 자연스럽게 나온다.

**결론: 세우지 않는다.** 공유할 코드가 전체의 2%고, 그 2%는 레포에서 가장 안 바뀌는
파일들이다. 아래는 그 판단의 근거와, 언제 이 판단을 다시 보아야 하는지의 조건이다.

## 실측 (2026-10-27)

quiz는 `main`(`30277ce`), blog은 같은 날 `main`을 클론해 쟀다. 센 것은 `.ts`·`.astro`·`.mjs`·
`.css` 파일의 **고유 줄**이다 — 공백을 지우고 25자 미만을 버린 뒤 중복을 접었다. 글 본문
(`site/src/content/blog`)은 코드가 아니라 제외했다.

| | blog | quiz | 양쪽 동일 |
|---|---|---|---|
| 소스 고유 줄 | 3,085 | 5,125 | **99** (≈2%) |
| CSS 커스텀 속성 | 52개 | 69개 | 이름 겹침 **1개** |

겹치는 CSS 속성 이름은 `--shell-width` 하나뿐이고 값도 다르다(blog `1240px`). 두 사이트는
디자인 토큰을 공유한 적이 없다.

재현 명령:

```bash
export LC_ALL=C   # 한글이 섞인 줄을 comm 에 넣으려면 두 쪽의 정렬 규칙이 같아야 한다
norm() { find "$1" -type f \( -name '*.ts' -o -name '*.astro' -o -name '*.mjs' -o -name '*.css' \) \
  -not -path '*content/blog*' -exec cat {} + | tr -d ' \t' | awk 'length($0)>=25' | sort -u; }
norm <blog>/site/src > /tmp/bl.txt
norm <quiz>/src      > /tmp/ql.txt
comm -12 /tmp/bl.txt /tmp/ql.txt | wc -l
```

### 그 99줄의 정체

| 무엇 | 분량 | 성격 |
|---|---|---|
| `src/lib/author.ts` 상수 | 16줄 | 글자까지 동일한 유일한 진짜 중복 |
| 궤도 그림의 역학 | 28줄 | `LinkFlow.astro`(206줄) ↔ `McpOrbit.astro`(509줄) |
| 소셜 아이콘 SVG `path` | 3줄 | GitHub·LinkedIn·메일 |
| 다크 테마 셀렉터·`@media` | 6줄 | 프레임워크 관례에 가까운 보일러플레이트 |

궤도 그림은 겹치는 것이 좌표 계산(`cos`/`sin` → `left`/`top`)과 pulse 타이머, 클래스 이름뿐이다.
노드 데이터와 문구는 완전히 다르고 블로그 쪽은 이미 2.5배로 따로 자랐다 — 저쪽은 글 한 편이
매일 도는 것을 그리고 이쪽은 연결 맞추기가 매주 도는 것을 그린다.

### 겹치지 않는 것

- **런타임**: blog은 Supabase를 쓰지 않는다(글 한 편에서 주제로 다룰 뿐). 이 레포의
  `auth`·`history`·`wrong-note`·`supabase`는 전부 이쪽 전용이다.
- **게이트**: blog의 `validate-publish.mjs`는 발행 호출 인자(섹션·슬러그·태그)를 막고,
  이쪽 `style-guard.mjs`·`written-merge.mjs`는 읽기 폭 토큰과 형광펜·정답 유출을 막는다.
  공통분모가 없다.
- **푸터·헤더**: `SiteFooter.astro` 22줄 대 다단 그리드 푸터. 서로 남남이다.
- **패키지 매니저**: blog은 pnpm 워크스페이스(`packageManager` 고정), 이쪽은 npm.
  공용 패키지를 끼우려면 둘 중 하나를 옮겨야 한다.
- **마크다운**: 이쪽 `src/lib/md.ts`는 세 층 강조(형광펜·굵기·값 칩)를 직접 펴는 40줄이고,
  blog은 Astro 콘텐츠 컬렉션과 remark 플러그인을 쓴다. 입력 형식부터 다르다.

### 중복 파일은 레포에서 가장 안 바뀌는 파일이다

quiz 커밋 248건(2026-08-15 이후) 중

- `src/lib/author.ts` 를 건드린 커밋: **1건** — 생성 커밋(2026-10-07 `"머리를 블로그 코드
  그대로 옮긴다"`)
- `src/components/LinkFlow.astro` 를 건드린 커밋: **1건**

뽑아 둘 가치는 "앞으로 양쪽을 같이 고칠 일이 얼마나 되나"에서 나오는데, 이 두 파일은 그 일이
한 번도 없었다. blog 쪽도 각 1건이지만 이 숫자는 얕은 클론(30커밋)만 본 것이라 덜 확실하다.

## 진짜 연관은 코드가 아니라 데이터다

`scripts/blog-sync.mjs`가 blog의 RSS, GitHub 트리 API, raw 마크다운을 HTTP로 읽는다. 이미
레포 경계를 넘는 계약이고, core 레포를 세워도 이 결합은 한 줄도 줄지 않는다. 줄이고 싶다면
대상은 공용 패키지가 아니라 **이 계약의 모양**이다 — 예를 들어 RSS와 트리 API를 각각
파싱하는 대신 blog이 내보내는 JSON 하나를 읽는 쪽.

## 세우면 무엇이 실패하나

core 레포를 세운 뒤 6개월이 지나 실패했다면, 가장 그럴듯한 이유 셋:

1. **들어간 건 상수 16줄뿐이었다.** 대신 두 레포에 워크스페이스 연결·버전 범프·릴리스
   순서가 생겨, 커밋 하나가 세 레포를 건드리게 됐다. 공유할 양이 유지비를 넘는다는 전제가
   깨진 것이다.
2. **토큰을 통일하려다 한쪽 화면이 망가졌다.** 에디토리얼 블로그와 학습 도구가 같은
   팔레트에 묶였다. 이름 겹침이 1개였다는 실측이 미리 준 경고였다.
3. **매일 자동 발행이 멈췄다.** blog의 `daily-post.yml`이 core 미반영 상태로 빌드에 실패했다.
   발행 파이프라인에 레포 하나가 더 끼었기 때문이다.

## 대신 한 것 · 안 한 것

**한 것 — 중복 스킬 제거.** `.claude/skills/ponytail/SKILL.md`가 두 레포에 바이트 동일로
들어 있었다(각 120줄). 같은 스킬을 `~/claude-shared/core-tools`가 플러그인으로 이미 모든
레포에 공급하므로(본문 동일, 설명문만 더 짧게 다시 쓴 판), 레포 사본은 하는 일 없이 두
벌로 남아 있었다. 이쪽 사본을 지웠다.

`.claude/agents/design-director.md`와 `.claude/skills/responsive-check/`도 두 레포에 있지만
**지우지 않는다** — claude-shared가 공급하지 않는 것이고, 두 레포 사본이 서로 갈라져 있어
(각각 94줄·11줄 차이) 그 차이가 레포 사정을 담고 있을 수 있다. 바이트 동일한 것만 지우는
것이 안전선이다.

**안 한 것:**

- `author.ts`를 공용화하지 않는다. 16줄 상수에 레포를 세우면 유지비가 원본보다 크다. 이쪽
  파일 머리말이 "블로그의 `site/src/lib/author.ts`와 같은 모양"이라고 적어 추적 경로를
  남기고 있다.
- 궤도 그림을 공용 컴포넌트로 만들지 않는다. 겹침이 28줄인데 두 화면의 요구가 한
  컴포넌트로 들어오면 양쪽이 같이 복잡해진다.

## 다시 볼 조건

아래 중 하나가 참이 되면 이 판단을 다시 센다. 조건을 미리 적어 두는 이유는, "뽑지 않는다"가
한 번 정해지면 근거가 바뀐 뒤에도 그대로 굳기 때문이다.

| 조건 | 지금 값 |
|---|---|
| 같은 코드를 양쪽에 **동시 수정**한 일이 한 분기에 2건을 넘는다 | 0건 |
| 공통 줄이 **300줄**을 넘는다 | 99줄 |
| CSS 커스텀 속성 이름 겹침이 **20개**를 넘는다 | 1개 |
| quiz가 blog의 **마크다운 표기 규칙 자체**를 공유해야 한다 | 서로 다른 형식(`md.ts` 대 remark) |

첫 줄이 가장 중요하고 가장 싸게 센다 — 공통 줄 수는 위 재현 명령으로 언제든 다시 재면 된다.
마지막 줄이 참이 되는 날은 가장 멀어 보인다. 이 넷 중 어느 것도 아직 참이 아니라면,
두 레포가 각자 자라는 것이 비용이 아니라 그 사이트들이 서로 다른 물건이라는 사실의 반영이다.
